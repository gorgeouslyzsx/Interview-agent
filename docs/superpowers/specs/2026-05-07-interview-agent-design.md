# 模拟面试 Agent 设计文档

## 1. 项目目标

做一个精简风格的模拟面试平台。用户进入后只需要选择自己的角色：

- **我是面试人员**：用户回答问题，AI 扮演面试官。
- **我是面试官**：用户提出问题，AI 扮演候选人。

本项目要体现几个适合写进简历的 Agent 工程能力：

- Prompt Cache
- 身份级记忆
- JD 约束
- RAG 面试题库
- Guardrail
- Context Engineering
- 简单 Harness 测试

## 2. 核心流程

### 2.1 用户作为面试人员

用户是候选人，AI 是面试官。

流程：

1. 用户选择 **我是面试人员**。
2. 用户创建或选择一个候选人身份。
3. 用户上传JD和个人简历
4. 用户配置面试：
   - 面试风格：友好型、一般型、技术型、压力型。
   - 难度：简单、中等、困难。
5. AI 根据 JD、题库、难度和身份记忆开始提问。
6. 用户回答问题。
7. AI 根据回答继续追问。
8. 面试结束后，AI 生成复盘报告。
9. 系统更新该候选人身份的记忆。

复盘报告包括：

- 总体评价。
- 技能评分。
- 回答亮点。
- 薄弱点。
- 改进建议。
- 下一次建议练习的方向。

### 2.2 用户作为面试官

用户是面试官，AI 是候选人。

流程：

1. 用户选择 **我是面试官**。
2. 用户创建或选择一个模拟候选人身份。
3. 用户上传或粘贴 JD。
4. 用户向 AI 候选人提问。
5. AI 根据候选人身份进行回答。
6. 面试结束后，系统可以给出简单总结，例如问题覆盖是否充分、是否追问到关键点。

模拟候选人身份可以配置：

- 工作年限。
- 技术栈。
- 强项。
- 弱项。
- 表达风格。
- 项目经历概要。

## 3. 主要功能

### 3.1 角色选择

首页只保留两个入口：

| 用户选择 | AI 扮演 | 目标 |
| --- | --- | --- |
| 我是面试人员 | 面试官 | 帮用户练习被面试 |
| 我是面试官 | 候选人 | 帮用户练习提问和判断 |

### 3.2 身份管理

每个模式下都可以创建多个身份，每个身份有自己的记忆。

用户作为面试人员时，身份是候选人身份，例如：

- Java 后端三年经验。
- 前端应届生。
- 算法薄弱候选人。
- 项目经验丰富候选人。

用户作为面试官时，身份是模拟候选人身份，例如：

- 基础扎实但表达一般。
- 项目很多但细节不清楚。
- 算法强但工程经验弱。
- 三年后端候选人。

每个身份记录：

- 基础资料。
- 历史面试记录。
- 已暴露的薄弱点。
- 表现较好的能力。
- 系统给过的建议。
- 最近一次会话摘要。

### 3.3 JD 上传

用户可以上传或粘贴 JD。

系统从 JD 中抽取：

- 岗位名称。
- 必备技能。
- 加分技能。
- 工作职责。
- 年限要求。
- 面试重点。

JD 用于约束问题范围，避免 AI 随机提问。

### 3.4 面试配置

只有在 **用户作为面试人员，AI 作为面试官** 时，才需要配置面试风格。

风格包括：

- **友好型**：语气温和，压力较低，适合新手练习。
- **一般型**：标准面试节奏。
- **技术型**：更关注技术细节和追问深度。
- **压力型**：节奏更快，追问更直接，难度更高。

难度包括：

- 简单。
- 中等。
- 困难。

### 3.5 RAG 面试题库

平台支持上传面试题库。

每道题可以包含：

- 题目。
- 技能标签。
- 难度。
- 题型。
- 参考答案。
- 评分点。

面试时，系统根据以下信息检索题目：

- JD 技能要求。
- 面试难度。
- 当前面试主题。
- 身份记忆中的薄弱点。

参考答案只用于辅助评分和生成追问，不应该直接泄露给候选人。

### 3.6 面试复盘

面试结束后生成复盘报告。

报告内容：

- 总体结果。
- 各技能项评分。
- 回答中的亮点。
- 回答中的问题。
- 缺失知识点。
- 改进建议。
- 下次练习建议。

评分必须引用用户回答中的证据，避免空泛评价。

## 4. UI 设计

UI 目标是精简、前沿、专业，不做花哨大屏，也不做传统后台系统的厚重表格感。整体应该像一个现代 AI 工作台：信息清楚、操作路径短、视觉克制。

### 4.1 视觉风格

整体风格：

- 极简 AI 工作台。
- 浅色为主，支持后续扩展深色模式。
- 大面积留白，少量边框和浅阴影区分层级。
- 不使用大面积渐变、夸张插画、复杂背景。
- 不做营销式首页，第一屏就是可用的面试入口。

推荐配色：

- 背景：近白色或浅灰白。
- 主文字：深灰黑。
- 次级文字：中性灰。
- 强调色：冷静的蓝色或青色，用于主按钮、当前状态、进度。
- 风险/薄弱点：少量橙色或红色。
- 通过/优势：少量绿色。

视觉细节：

- 卡片圆角控制在 8px 左右。
- 边框使用 1px 浅灰线。
- 阴影非常轻，只用于浮层或当前活动区域。
- 字体层级克制，避免大标题堆砌。
- 图标使用统一线性图标风格，例如 lucide icons。

### 4.2 页面结构

平台主要由 5 个页面组成：

1. **角色选择页**
2. **身份管理页**
3. **面试配置页**
4. **面试会话页**
5. **复盘报告页**

整体导航采用轻量侧边栏或顶部导航：

```text
左侧：身份 / 会话 / 题库
中间：当前主要操作区
右侧：JD 摘要 / 记忆摘要 / 面试状态
```

桌面端优先使用三栏布局。移动端切换为单栏布局，通过顶部 Tab 在聊天、JD、记忆、报告之间切换。

### 4.3 角色选择页

角色选择页不要做成宣传首页，而是直接让用户开始。

布局：

```text
顶部：产品名 + 简短副标题
中间：两个角色入口
底部：最近会话 / 快速继续
```

两个入口：

- 我是面试人员
- 我是面试官

设计要求：

- 两个入口视觉权重一致。
- 使用简短说明，不写大段介绍。
- 当前选择用边框、背景和小图标强调。
- 选择后直接进入身份选择或面试配置。

### 4.4 身份管理页

身份管理页要像一个轻量资料库。

每个身份展示：

- 身份名称。
- 模式：面试人员练习 / 面试官练习。
- 技术方向。
- 最近练习时间。
- 主要薄弱点或特点。

交互：

- 新建身份。
- 编辑身份。
- 选择身份开始面试。
- 查看该身份历史报告。

视觉上使用紧凑卡片列表，不做大块装饰卡片。重点是让用户快速分辨不同身份。

### 4.5 面试配置页

面试配置页是一个简单的三步配置：

```text
1. 选择身份
2. 上传或粘贴 JD
3. 设置面试风格和难度
```

如果用户选择 **我是面试官**，则不展示面试官风格选择，只展示模拟候选人身份和 JD。

如果用户选择 **我是面试人员**，展示：

- 面试风格：友好型、一般型、技术型、压力型。
- 难度：简单、中等、困难。
- 题库来源：默认题库 / 上传题库。

控件建议：

- 角色、风格、难度使用 segmented control。
- JD 上传使用简洁 dropzone。
- 题库来源使用下拉选择。
- 开始面试按钮固定在配置区底部。

### 4.6 面试会话页

这是最核心的页面，应该像一个专注的面试工作台。

桌面布局：

```text
左栏：身份和会话列表
中间：面试聊天区
右栏：JD 摘要、当前考察点、记忆提示、面试进度
```

中间聊天区：

- AI 问题或回答展示在主区域。
- 用户输入框固定在底部。
- 支持“结束面试”“生成复盘”按钮。
- 面试中显示当前轮次和当前考察技能。

右侧辅助区：

- JD 摘要。
- 当前技能标签。
- 已问问题数量。
- 候选人薄弱点。
- RAG 命中的题库来源。

右侧信息不要抢主区域注意力，只做辅助提示。

### 4.7 复盘报告页

复盘页要适合用户快速看懂结果，也适合截图放进项目展示。

报告结构：

- 顶部：总分、结果等级、主要结论。
- 中部：技能评分矩阵。
- 下方：证据化反馈。
- 底部：下一步练习建议。

评分展示：

```text
Java 基础      7/10
项目表达       8/10
系统设计       5/10
沟通清晰度     7/10
```

每个问题反馈都要包含：

- 问题。
- 用户回答摘要。
- 评价。
- 改进建议。

视觉上不要做复杂图表，优先使用条形进度、标签和简短说明。

### 4.8 组件规范

主要组件：

- RoleSwitch：角色选择。
- IdentityCard：身份卡片。
- JDPanel：JD 上传和解析结果。
- InterviewConfigPanel：面试配置。
- ChatPanel：面试聊天。
- ContextSidePanel：JD、记忆、进度辅助信息。
- ReportSummary：复盘总览。
- SkillScoreList：技能评分列表。
- EvidenceFeedbackList：证据化反馈列表。

按钮：

- 主按钮用于开始面试、生成报告。
- 次按钮用于保存、编辑、重新生成。
- 危险按钮只用于删除身份或删除会话。

状态：

- 空状态要给出明确下一步，例如“创建身份开始第一次模拟面试”。
- 加载状态使用轻量 skeleton。
- 错误状态说明原因，并提供重试。

### 4.9 UI 简历表达

可以写成：

- 设计前沿精简风格的 AI 面试工作台，采用角色选择、配置引导、三栏会话和证据化复盘结构，降低用户开始模拟面试的操作成本。
- 将 JD 摘要、身份记忆、RAG 命中题目和面试进度整合到 Context Side Panel，使用户在面试过程中可以清楚理解 Agent 的上下文来源。
- 设计结构化复盘报告页面，用技能评分、证据反馈和下一步建议呈现面试结果，提升模拟面试的可解释性。

## 5. 核心架构

```text
前端
  -> 角色选择
  -> 身份管理
  -> JD 上传
  -> 面试配置
  -> 面试聊天
  -> 复盘报告

后端
  -> Interview Orchestrator
  -> Identity Memory
  -> JD Parser
  -> RAG Question Bank
  -> Context Builder
  -> Guardrail
  -> Evaluation
  -> LLM Client
```

### 5.1 Interview Orchestrator

负责控制面试流程。

职责：

- 根据用户选择确定 AI 扮演的角色。
- 加载身份记忆。
- 加载 JD 信息。
- 检索相关题目。
- 组织上下文。
- 调用 LLM。
- 保存对话。
- 生成复盘报告。
- 面试结束后更新记忆。

### 5.2 Context Builder

负责每一轮 LLM 调用前的上下文组装。

上下文包括：

- 系统规则。
- 用户角色和 AI 角色。
- 身份资料。
- 身份记忆。
- JD 信息。
- 面试风格。
- 难度。
- RAG 检索结果。
- 最近几轮对话。
- 输出格式要求。

上下文优先级：

1. 系统规则和安全规则。
2. 角色规则。
3. JD 约束。
4. 面试配置。
5. 身份记忆。
6. RAG 题库内容。
7. 最近对话。

### 5.3 Memory Service

负责维护身份级记忆。

记忆类型：

- 身份长期记忆。
- 会话摘要。
- 薄弱点记忆。
- 强项记忆。
- 历史反馈。

记忆更新流程：

```text
面试对话 -> 提取有价值信息 -> 分类 -> 与旧记忆合并 -> 保存
```

不直接把所有聊天记录都写入长期记忆，只保存对后续面试有用的信息。

### 5.4 Guardrail

Guardrail 用来保证面试过程稳定、安全、可控。

输入侧：

- 检测 JD 或题库里的 Prompt Injection。
- 忽略试图覆盖系统规则的内容。

上下文侧：

- 不把参考答案暴露给候选人。
- 不混用不同身份的记忆。

输出侧：

- 不泄露隐藏评分规则和参考答案。
- 不输出歧视性评价。
- 不做没有证据的评分。

评估侧：

- 每个评分都要有原因。
- 反馈必须基于用户真实回答。

### 5.5 Prompt Cache 策略

Prompt 拆成稳定部分和动态部分。

稳定部分适合缓存：

- 角色规则。
- 面试行为规则。
- 面试风格定义。
- 评分标准。
- Guardrail 规则。
- 输出格式。

动态部分每轮变化：

- 当前 JD。
- 当前身份记忆。
- RAG 检索结果。
- 最近对话。
- 用户最新输入。

这样可以减少多轮面试中重复发送固定规则带来的 token 消耗。

### 5.6 RAG 题库

题库处理流程：

```text
上传文件 -> 解析题目 -> 添加标签 -> 生成向量 -> 存储 -> 面试时检索
```

检索依据：

- JD 技能。
- 难度。
- 面试风格。
- 当前主题。
- 身份薄弱点。

RAG 的目标不是替代模型，而是让提问更贴合岗位和题库。

### 5.7 Harness 测试

项目需要一个简单的 Agent 测试 Harness。

测试内容：

- 角色切换是否正确。
- JD 是否影响问题生成。
- 不同面试风格是否有明显区别。
- 不同身份的记忆是否隔离。
- 候选人模式下是否不会泄露参考答案。
- 复盘报告是否包含证据。
- JD 中的 Prompt Injection 是否被忽略。

这个 Harness 不需要很大，一组固定测试输入和检查规则即可。

```ts
type Identity = {
  id: string;
  userId: string;
  mode: "candidate_practice" | "interviewer_practice";
  name: string;
  profile: string;
  memorySummary: string;
  createdAt: string;
  updatedAt: string;
};
```

### 6.2 InterviewSession

```ts
type InterviewSession = {
  id: string;
  userId: string;
  userRole: "candidate" | "interviewer";
  aiRole: "interviewer" | "candidate";
  identityId: string;
  jdId?: string;
  style?: "friendly" | "normal" | "technical" | "pressure";
  difficulty?: "easy" | "medium" | "hard";
  status: "active" | "completed";

  createdAt: string;
  updatedAt: string;
};
```

```ts
type Message = {
  id: string;
  sessionId: string;
  role: "user" | "assistant";
```

```ts
type JDProfile = {
```

```ts
type QuestionItem = {
  id: string;
  userId: string;
```

## 7. MVP 范围

第一版需要做：

- 角色选择。
- 身份创建。
- JD 粘贴或上传。
- 面试风格和难度配置。
- 聊天式模拟面试。
- 基础身份记忆。
- 基础题库上传。
- RAG 检索题目。
- 面试结束复盘。
- 简单 Guardrail。
- 简单 Harness 测试。

第一版不做：

- 语音面试。
- 视频面试。
- 在线代码编辑器。
- 复杂数据看板。
- 多 Agent 协作。
- 具体公司面试官模拟。

## 8. 简历表达

可以写成：

- 设计并实现模拟面试平台，支持用户选择作为面试人员或面试官，AI 自动扮演对手方完成多轮面试。
- 设计前沿精简风格的 AI 面试工作台，通过角色入口、三步配置、三栏会话区和结构化复盘报告完成完整模拟面试体验。
- 实现身份级记忆机制，为不同候选人或模拟候选人身份维护独立的面试记录、薄弱点、强项和历史反馈。
- 基于上传 JD 和 RAG 面试题库生成岗位相关问题，支持技能标签、难度分层和面试风格控制。
- 设计 Prompt Cache 友好的上下文分层方案，将角色规则、评分标准、Guardrail 和输出格式与动态 JD、记忆、对话上下文分离。
- 加入 Guardrail，防止参考答案泄露、上传内容 Prompt Injection、身份记忆串扰和无依据评分。
- 构建轻量级 Agent Evaluation Harness，验证角色切换、RAG 相关性、记忆隔离、Guardrail 和复盘报告质量。

## 9. 成功标准

这个设计完成后，平台应满足：

- 用户能清楚选择自己是面试人员还是面试官。
- UI 风格精简、现代，用户能在三步内开始一次模拟面试。
- AI 能稳定扮演对手方。
- JD 能影响问题生成。
